# 椅子之后

为 `/@lightjunction/web/` 制作的实时 3D ASCII 核爆场景。开场是一把椅子和一个瘫坐的人，镜头在前六秒从第三人称进入他的眼睛。第八秒远处出现核爆火球，8.5 秒起可以移动、转身、坐回椅子、喝咖啡或走进身后的地下避难所。实际进入地下室并关好门才能挡住冲击波；门外关门、室内开门都不能保护玩家。时间均指场景内时间，暂停和隐藏页面不计入。

`scene.js` 在运行时采样箱体、椭球、肢体、杯壁和杯把表面，进行透视投影、深度缓冲和表面法线光照，再把字符写入一个 `pre`。`world_geometry.js` 提供入口、十二级楼梯、地下房间、门和废墟的纯几何数据；地下室还逐字符计算射线与墙、地板和顶面的交点，填入深度缓冲，保持连续封闭的空间。世界只使用 7-bit ASCII，中文状态和操作说明在字符场景外。桌面使用 112×60 字符网格，宽度小于 600px 时使用 76×56；字符大小按可用舞台尺寸计算。场景保留椅子、人体、旁桌与有杯壁、杯口和把手的咖啡杯、第一人称手部和核爆体积，并增加地下生路及爆后弹坑、废墟。

模拟状态在每次 `requestAnimationFrame` 回调推进，绘制目标为桌面 30 fps（间隔 `1000/30ms`）、宽度小于 600px 时 20 fps（`50ms`）。绘制后保留本次 rAF 间隔的余数，校准下一次绘制时刻，避免临界时刻误差持续累积。这是调度目标，实际帧率取决于硬件和渲染成本；输入响应及成本由作者本次实测确认，本文不宣称已达到稳定帧率。

## 操作

8.5 秒后且未暂停、未死亡时开放场景交互。页面按钮与键盘操作使用相同状态约束。

| 输入 | 行为 |
| --- | --- |
| WASD / 方向键 | 按视角方向移动，移动会自动起身。 |
| Shift | 按住加速跑。 |
| 桌面点击场景 / 移动鼠标 | 请求捕获鼠标后用相对移动转头；向右移动向右看。 |
| 拖动场景 | 捕获失败或触屏时拖动转头，俯仰范围为 ±1.28 弧度；直接看向别处会取消 B/F 转向目标。 |
| E / 起身、坐回、避难门 | 接近地下门时优先开关门；其他位置切换站坐，回到椅子附近才能坐回。避难门也有独立按钮。 |
| B / 背对，不看 | 转向背对核爆的方向。 |
| F / 默默面对 | 转向核爆的方向。 |
| C / 喝咖啡 | 在旁桌附近喝一口；手和杯子抬起约 2.5 秒，两次操作至少相隔三秒。 |
| P / 暂停、继续 | 冻结或恢复场景时间，同时清除正在按住的移动输入。 |
| Esc | 释放鼠标捕获；页面收到 Esc 键事件时也切换暂停。 |
| R / 重开 | 重置本轮时间、位置、视角、站坐、咖啡、门和生存状态。 |

手机显示 A/W/S/D 和“跑”按钮，可用不同手指同时移动、加速和拖动视角。键盘与各触点独立保存，松开一个触点只释放它自己的输入；取消触摸或丢失指针捕获也会释放对应输入。

避难所入口在椅子后方，楼梯从 `z=-2` 走到 `z=-5.05`，地面降到 `y=-2.6`。地下室范围为 `x=±2.6`、`z=-5.05..-9.6`。走近门时先按 E 开门，等门打开后沿楼梯真实走进去，再关门并等“门已关好”。保护条件是玩家在室内、门设为关闭且旋转角度已回到 `≤0.04` 弧度；冲击波结束前重新开门会失去保护。

活下来后，在场景时间 28 秒进入爆后阶段，可以开门、走上楼梯，查看地面弹坑和废墟，保持自己的位置和视角，想重开时再按 R。未受保护的玩家死亡后禁止移动、转身、开关门和喝咖啡，镜头降低到当前地面，六秒后进入下一轮，也可立即重开。

系统选择减少动态效果时，开场保持静止，必须点击“开始互动”才推进时间；重开与死亡后的下一轮也重新等待明确开始。页面隐藏时停止推进时间并清除输入；可见页面失去焦点时明确暂停，回来后需要继续。暂停、失焦、隐藏、重开和死亡都会释放鼠标捕获，并使尚未完成的旧捕获申请失效；即使取消后立即继续，旧申请晚到也会退出。捕获状态变化也会清除移动与拖动输入。运行中切换到减少动态效果也会暂停。

## 构建与验收

在仓库根目录执行：

```sh
python examples/lightjunction-ascii/build.py
uv run --with playwright python examples/lightjunction-ascii/check_interactive_browser.py
uv run --with playwright python examples/lightjunction-ascii/check_interactive_browser.py --pointer-lock-only
```

部署后可在同一验收入口加 `--origin https://msg.lmm.best`。它会核对线上响应的完整 HTML 与本地构建逐字节哈希一致，并检查最终 CSP，再执行真实玩法；本地通过仍需单独完成这一步。

`build.py` 将 `world_geometry.js` 和 `scene.js` 拼成一个内联脚本，再嵌入 `template.html`，生成唯一发布文件 `index.html`，并输出 HTML SHA256、大小和该脚本的 CSP SHA256 pin。运行时无需 WebGL、外部字体、图片、音频或外联请求。作者名 `@lightjunction` 是不可点击的普通文字，页面没有链接、导航或表单。交互托管使用 `sandbox allow-scripts allow-pointer-lock` 并保持 opaque origin；`script-src` 只允许本次构建对应的脚本哈希，不加入 `allow-same-origin`、脚本通配符或 `unsafe-inline` 脚本权限。CSP 还显式将 `script-src-attr`、`connect-src`、`frame-src`、`object-src` 和 `worker-src` 设为 `'none'`，保留 `base-uri`、`form-action` 和 `frame-ancestors` 的禁止规则。最终构建的哈希与托管配置由协调者绑定，这份文档不固定尚在变化的构建哈希。

`check_interactive_browser.py` 使用本地 HTTP 服务、从发布文件计算的 pinned-script CSP 和系统 `/usr/bin/chromium`。它在桌面 1440×1000 与手机 390×844 分别检查留在地面观看、室内开门死亡、门外关门死亡、室内关门存活四个分支。存活分支真实走下楼梯、开门入内、关好门等冲击波过去，再进入爆后阶段，开门走回地面并手动重开；死亡分支检查位置冻结、动作禁用和重开。公共检查包含纯 ASCII、opaque origin、水平溢出、控制台错误和仅有页面本身的请求。独立的 reduced-motion 场景检查静态等待、明确开始、暂停/继续、拖动、失焦释放输入和重开回等待。

主脚本的九个场景负责生存分支和减少动态效果流程。`--pointer-lock-only` 单独检查延迟的原生鼠标捕获：真实点击后将原生申请延后 300ms，暂停并立即继续，确认浏览器确实批准后应用仍释放旧申请，再检查新的捕获、向右转头、Esc 释放和重开。测试延迟只存在于浏览器测试环境。俯仰边界、真实失焦/隐藏及触屏多指移动/跑动/拖动由独立 QA 补充；不能只凭九个结果宣称全部输入已验收。

截图及机器记录写入 `.impeccable/review/`；机器记录为 `interactive-browser.json` 或 `pointer-lock-browser.json`，包含 HTML 哈希、脚本 pin、CSP 和各分支结果。这些是运行脚本后产生的本地证据，不是网站资产。本文记录验收入口和覆盖项，不宣称本地验收、最终设计评审或公网签名发布已经完成。

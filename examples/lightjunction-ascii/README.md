# 椅子之后

为 `/@lightjunction/web/` 制作的自包含 ASCII 场景。开场是一把有椅背、座面和四条腿的椅子；3.6 秒后出现火球、地面冲击波、字符碎屑和升起的蘑菇云。18 秒循环，64 帧。

网页中的物体只使用 7-bit ASCII 字符。它们来自真实 3D 表面采样、透视投影、深度缓冲和表面法线光照；相机缓慢绕行。预计算帧由 CSS 离散播放，网页没有 JavaScript、WebGL、外部字体、图片、音频或网络请求。它适用于 MSG 用户网站现有的 opaque-origin CSP sandbox，无须改变服务器权限。

64 帧共用投影容器上的单一 CSS 时钟：可继承的整数属性 `--frame` 按 `steps(64, end)` 推进，各帧通过固定索引与 `calc`/`max` 透明度计算显示恰好一帧。时钟先停在第 0 帧，直到所有帧之后的页脚 `#scene-ready` 被解析才开始播放，因此流式下载期间保持开场椅子，不会让不同帧各自起跑。

暂停使用原生复选框，以 `!important` 暂停父容器时钟并保持当前画面；聚焦后按空格也可切换。重播重新打开当前网站。系统选择减少动态效果时，默认显示独立的静态椅子，用户明确选择播放后恢复同一时钟，暂停仍有效。场景不会快速黑白闪烁；火球的变化局限在物体本身。

## 生成与验收

在仓库根目录执行：

```sh
python examples/lightjunction-ascii/generate.py
uv run --with playwright python examples/lightjunction-ascii/check_browser.py
```

生成器只使用 Python 标准库，随机碎屑固定 seed 为 781。`index.html` 是待发布的单个文件，大小应小于 400 KiB。浏览器检查使用本地 HTTP 服务和 MSG 实际托管 CSP，覆盖桌面 1440×1000、手机 390×844、静态减少动态效果及明确播放，以及 390px 流式下载。流式服务每 70ms 发送 8 KiB，让不同帧跨多个渲染时刻完成解析。测试需要系统 `/usr/bin/chromium`。

每个播放场景都实际观察完整 0–63 帧和循环回绕，核对只有一个父容器动画、恰好一帧透明度可见且与时钟一致。鼠标与键盘暂停检查同时核对按透明度计算的可见帧和动画时间保持不变，再检查继续播放；另检查页面溢出、脚本和外部请求。`check_browser.py` 的 `inspect(..., slow=True)` 可供协调者调用公网 origin，通过 CDP 把下载速率限制为 32 KB/s（32000 B/s）；这是独立的公网验收入口，本地通过不代表公网已通过。
